How CloudVeil protects your documents

Every file is encrypted with its own unique key before it ever leaves the server. Only ciphertext is stored; the master key never leaves Azure Key Vault.

  1. 1 · Encrypt

    A fresh 256-bit AES-GCM data key (DEK) and nonce are generated per file. The file is encrypted and bound to its owner with authenticated additional data (AAD).

  2. 2 · Wrap the key

    The DEK is wrapped (RSA-OAEP-256) by the master key (KEK) in Azure Key Vault. Only the wrapped key is stored in the database — never the plaintext key.

  3. 3 · Store

    The ciphertext goes to a private Azure Blob container as files/<random-uuid>.bin — no original filename, no readable content.

  4. 4 · Replicate

    Object replication copies the ciphertext to a second Azure region for durability — still only ciphertext.

  5. 5 · Authorize & decrypt

    On download, CloudVeil checks authentication and permissions first. Only then is the DEK unwrapped in Key Vault and the file decrypted and integrity-checked (SHA-256). Tampering is detected and rejected.

  6. 6 · Audit

    Every login, upload, download, share and denial is written to an append-only audit log.

Note: decryption is performed server-side, so CloudVeil provides strong encryption at rest with controlled decryption — not end-to-end encryption.
